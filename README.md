# 사내 그룹웨어 (구글 드라이브 연동)

구글 드라이브를 데이터 저장소로 쓰는 사내 그룹웨어입니다. 대시보드, 법인정보, 공지사항, 일정/캘린더,
전자결재, 근태관리, SNS 운영(콘텐츠 캘린더 + 승인워크플로우)까지 포함되어 있어요.

로그인한 사람의 구글 계정 권한으로 구글 드라이브의 JSON 파일에 데이터를 읽고 씁니다. 같은 "데이터 폴더"를
동료들과 공유하면 모두 같은 데이터를 보고 씁니다.

---

## 1단계. Google Cloud에서 OAuth 클라이언트 ID 만들기

이 앱이 구글 로그인 + 드라이브 접근 권한을 받으려면 딱 한 번, 구글 계정 소유자가 아래 설정을 해야 해요.
(다른 사람이 대신 만들어줄 수 없어요 — 본인 구글 계정으로 진행해주세요.)

1. https://console.cloud.google.com/ 접속 → 우측 상단 프로젝트 선택 → **새 프로젝트** 생성 (이름 예: `groupware`)
2. 좌측 메뉴 **API 및 서비스 → 라이브러리** 에서 `Google Drive API` 검색 → **사용 설정**
3. **API 및 서비스 → OAuth 동의 화면**
   - User Type: **외부(External)** 선택 (일반 구글 계정이면)
   - 앱 이름: `사내 그룹웨어`, 사용자 지원 이메일: 본인 이메일
   - 범위(Scopes)는 기본값으로 두고 저장
   - **테스트 사용자**에 그룹웨어를 쓸 동료들의 구글 이메일을 모두 추가 (앱이 "게시" 상태가 아니면 테스트
     사용자로 등록된 사람만 로그인 가능해요)
4. **API 및 서비스 → 사용자 인증 정보 → + 사용자 인증 정보 만들기**
   - **API 키** 생성 → 이 값을 `js/config.js` 의 `API_KEY` 에 붙여넣기
     (선택: "키 제한사항"에서 HTTP 리퍼러를 본인 배포 주소로 제한하면 더 안전해요)
   - **OAuth 클라이언트 ID** 생성 → 애플리케이션 유형: **웹 애플리케이션**
     - 이름: `groupware-web`
     - **승인된 자바스크립트 원본(Authorized JavaScript origins)** 에 아래 주소 추가
       (2단계에서 GitHub Pages 주소를 먼저 확인한 뒤 이 값을 넣어도 됩니다):
       - `https://<본인GitHub아이디>.github.io`
       - 로컬 테스트용으로 `http://localhost:5500` 같은 것도 추가해두면 편해요
     - 만들기 → 발급된 **클라이언트 ID**를 `js/config.js` 의 `CLIENT_ID` 에 붙여넣기

5. `js/config.js` 를 열어 `CLIENT_ID`, `API_KEY` 두 값을 실제 값으로 교체 후 저장하세요.

> ✅ 이 프로젝트는 이미 VALIXLAB 구글 클라우드 프로젝트에 OAuth 클라이언트(`groupware-web`)와
> API 키(`groupware-api-key`)가 만들어져 있고, `js/config.js`에도 그 값이 채워져 있어요.
> 승인된 자바스크립트 원본은 `https://kss09876-alt.github.io` 로 등록해뒀습니다
> (GitHub 저장소: `kss09876-alt/groupware`).
> 다른 GitHub 아이디로 배포하시거나 도메인을 바꾸시면, Google Cloud Console의
> "API 및 서비스 → 사용자 인증 정보"에서 OAuth 클라이언트와 API 키의 승인된 원본을 새 주소로
> 수정해주셔야 해요.

## 2단계. GitHub Pages로 배포하기

1. GitHub(https://github.com) 에서 새 저장소(Repository) 생성 (예: `groupware`), Public으로 설정
2. 이 폴더(`groupware/`) 안의 모든 파일을 그 저장소에 업로드
   - GitHub 웹사이트에서 "Add file → Upload files" 로 드래그해서 올려도 되고,
   - git 을 쓸 줄 아시면 아래처럼 하셔도 됩니다:
     ```
     cd groupware
     git init
     git add .
     git commit -m "init groupware"
     git branch -M main
     git remote add origin https://github.com/<본인아이디>/groupware.git
     git push -u origin main
     ```
3. 저장소의 **Settings → Pages** 로 이동 → Source를 `main` 브랜치, `/ (root)` 로 설정 → Save
4. 몇 분 뒤 `https://<본인아이디>.github.io/groupware/` 주소로 접속 가능해집니다.
5. 이 주소(정확히는 origin인 `https://<본인아이디>.github.io` 부분)를 1단계 4번의
   "승인된 자바스크립트 원본"에 등록했는지 다시 확인하세요. 등록 안 하면 로그인 시 오류가 나요.

## 3단계. 첫 실행

1. 배포된 주소로 접속 → **Google 계정으로 로그인** 클릭 → 권한 동의
   (동의 화면에 "확인되지 않은 앱" 경고가 뜨면 "고급 → 이동" 클릭 — 본인이 만든 앱이라 안전해요.
   나중에 구글에 앱 심사를 요청하면 이 경고를 없앨 수 있어요.)
2. 회사에서 처음 쓰는 거라면 **"새 데이터 폴더 만들기"** 클릭
   → 로그인한 구글 계정의 드라이브에 `그룹웨어_data` 폴더가 생기고, 그 안에 각 기능별 JSON 파일이 만들어져요.
3. 동료들과 같이 쓰려면, 방금 만든 `그룹웨어_data` 폴더를 구글 드라이브에서 동료들에게 **공유(편집 가능)**
   해주세요. 동료는 로그인 후 **"기존 폴더 선택"** 으로 그 폴더를 골라 연결하면 같은 데이터를 보게 됩니다.

## 4단계. (선택) 법인정보 서류 "AI 자동 채우기" 설정

법인정보 탭에서 서류(등기부등본, 정관, 사업자등록증, 주주명부)를 업로드하면 그 옆에 **"🤖 AI로 채우기"**
버튼이 생겨요. 이 버튼은 AI(Google Gemini)가 서류 내용을 읽어서 법인정보 필드를 자동으로 채워주는
기능인데, API 키를 브라우저 코드에 그대로 넣으면 남이 훔쳐 쓸 수 있어서, 키를 안전하게 숨겨줄 작은
중계 서버(Cloudflare Worker, 무료)가 하나 더 필요해요. 아래 순서대로 딱 한 번만 설정하면 돼요.

### 4-1. Gemini API 키 발급받기 (본인 구글 계정으로)

1. https://aistudio.google.com/apikey 접속 (구글 계정으로 로그인)
2. **Create API key** 클릭 → 새 프로젝트를 만들거나 기존 프로젝트 선택
3. 발급된 API 키를 복사해두세요 (`AIza...` 로 시작). 이 키는 절대 그룹웨어 코드나 GitHub에 직접
   넣지 마세요 — 다음 단계에서 Cloudflare에만 비밀값으로 등록합니다.
4. 무료 사용량(하루 요청 수 제한)이 있어요. 개인/소규모 회사가 서류를 가끔 올릴 때 쓰기에는 충분해요.

### 4-2. Cloudflare Worker 만들기 (중계 서버, 무료)

1. https://dash.cloudflare.com/sign-up 에서 무료 계정을 만드세요 (없으시면).
2. 로그인 후 좌측 메뉴 **Workers & Pages** → **Create** → **Create Worker**
3. 이름을 정하고(예: `groupware-ai`) **Deploy** 클릭 (일단 기본 코드로 배포)
4. 배포된 Worker의 **Edit code** (또는 "Quick edit") 로 들어가서, 코드 전체를 지우고
   함께 받은 `worker.js` 파일 내용을 그대로 붙여넣으세요.
5. 코드 안의 `ALLOWED_ORIGIN` 값이 본인 GitHub Pages 주소(`https://kss09876-alt.github.io`)와
   일치하는지 확인하세요. (이미 그렇게 맞춰져 있어요.)
6. **Save and deploy** 클릭
7. Worker 설정 화면에서 **Settings → Variables and Secrets** (또는 "환경 변수") 로 이동
   → **Add** → 이름: `GEMINI_API_KEY`, 값: 4-1에서 복사한 키, 타입은 **Secret(암호화)** 로 선택 → 저장
   (다시 배포가 필요할 수 있어요 — 안내에 따라 진행하세요.)
8. Worker의 주소(예: `https://groupware-ai.<본인계정>.workers.dev`)를 복사해두세요.

### 4-3. 그룹웨어에 Worker 주소 연결하기

1. `js/config.js` 를 열어 `AI_WORKER_URL: ""` 부분에 4-2에서 복사한 Worker 주소를 넣으세요.
   예: `AI_WORKER_URL: "https://groupware-ai.본인계정.workers.dev",`
2. `index.html` 의 스크립트 주소 끝에 있는 `?v=4` 를 `?v=5` 처럼 숫자를 하나 올려주세요
   (안 그러면 동료들 브라우저에 예전 파일이 캐시되어 있을 수 있어요).
3. 수정한 파일들을 GitHub 저장소에 다시 업로드(덮어쓰기)하면 완료!
4. 법인정보 탭에서 서류를 업로드한 뒤 **"🤖 AI로 채우기"** 를 눌러보세요. AI가 읽어낸 내용을
   확인창에서 보여주고, **"이 내용으로 적용하기"** 를 눌러야만 실제로 저장돼요 (틀린 값이 섞여 있을
   수 있으니 항상 한 번 확인해주세요).

> 💡 이 기능 없이도 그룹웨어의 나머지 기능(캘린더, 공지, 결재, 근태, SNS, 법인정보 수동 입력)은
> 모두 정상적으로 동작해요. `AI_WORKER_URL`을 비워두면 "AI로 채우기" 버튼을 눌렀을 때
> 안내 메시지만 뜨고 아무 일도 일어나지 않습니다.

## 참고 사항 / 한계

- 사용 범위 스코프는 `drive.file` (앱이 만들었거나, 사용자가 직접 선택한 파일/폴더만 접근) 이라
  회사 전체 드라이브를 뒤지지 않고 딱 이 그룹웨어 데이터만 건드립니다. 더 안전해요.
- 동시에 여러 명이 "정확히 같은 순간"에 저장하면 마지막에 저장한 내용이 이전 내용을 덮어씁니다
  (소규모 팀 기준으로는 충분하지만, 사람이 아주 많다면 나중에 파일 잠금/버전 관리 로직을 추가하는 걸 권장해요).
- SNS 운영 탭은 콘텐츠 캘린더 + 담당자 배정 + 승인 워크플로우까지만 제공해요. 인스타그램/페이스북 등에
  실제로 자동 게시하려면 각 플랫폼의 공식 API와 별도 개발자 계정/토큰이 필요해서, 이후 단계로 확장할 수 있게
  구조만 잡아뒀어요.
- 법인정보(등기부/주주/세금일정 등) 탭은 정부 등기 시스템과 실시간 연동된 것이 아니라, 관리자가 직접
  입력·수정하는 방식이에요 (등기 변경 시 "법인정보 수정"에서 갱신).
